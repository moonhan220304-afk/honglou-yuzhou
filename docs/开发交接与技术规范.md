## 一、手机版「单独构建产物」说明

项目是 **Next.js 静态导出（`output:"export"`）**，桌面版和手机版是**两次独立构建、两份独立产物**，不是同一份产物响应式适配：

| 版本 | 构建命令 | 产物 | 线上路径 | basePath |
|---|---|---|---|---|
| 桌面 | `NEXT_PUBLIC_BASE_PATH=/honglou-yuzhou npm run build` | `out/` | `/honglou-yuzhou/` | `/honglou-yuzhou` |
| 手机 | `NEXT_PUBLIC_MOBILE=1 NEXT_PUBLIC_BASE_PATH=/honglou-yuzhou/m npm run build`（再 `mv out out-mobile`） | `out-mobile/` | `/honglou-yuzhou/m/` | `/honglou-yuzhou/m` |

- `NEXT_PUBLIC_MOBILE=1` 触发 `lib/mobile-build.ts` 的 `IS_MOBILE_BUILD`，切换手机专属组件（`MHome`/`MHeader`/`MobileNav`）。
- 两版**共用同一个后端**（`api-server.js` :4000）和**同一个 `hlm.db`**，会话 cookie `hlm_session` 是 `Path=/`，同域下登录态共享。

### ⚠️ API 前缀规则（最容易踩的坑）

`lib/api.ts` 里 `sitePath()` 与 `apiPath()` 是**两个独立函数**：

- `sitePath(p)`：页面跳转/图片等**静态资源**，加 basePath（移动版含 `/m`）。
- `apiPath(p)`：**API 请求**，自动去掉 `/m` 后缀（移动版打 `/honglou-yuzhou/api`，因为 nginx 只反代了 `/honglou-yuzhou/api/* → :4000`）。

**约定**：所有 fetch 请求用 `api(path)`（内部走 `apiPath`）；所有页面跳转/图片用 `sitePath()`。**禁止硬编码裸路径**。

## 四、技术要点 / 编码约定（固定下来）

1. **双构建**：桌面/移动分开 build，产物分开（`out/` 与 `out-mobile/`），本地验收用桌面版。
2. **路径**：一律 `sitePath()`（跳转/图片）和 `api()`（请求），不硬编码裸路径。
3. **图标**：只用 `components/icons.tsx` 的线性 SVG，禁 emoji/字符符号，`strokeWidth=1.6`。
4. **颜色**：只用 `@theme` 令牌，禁 `#c0392b` 等第三种红、禁 Tailwind 荧光色（emerald/amber/red-100）。
5. **卡片**：`card-print` + `rounded-2xl`（不是 `rounded-3xl`）。
6. **动画**：ease-out 无回弹；全站已加 `prefers-reduced-motion`。
7. **数据**：`docs/knowledge-base/` 是内容数据源（JSON），`server/data/hlm.db` 是社区运行时数据（不入库）。
8. **红线**：不部署、不动原文件夹 `opc-HLM`、不碰生产数据；改前备份。
